# JARVIS PR Review Bot — инструкция для разработчиков

Автоматический бот ревью PR через ИИ (Феникс/Qwen). Проверяет Perl-код на ошибки, безопасность и стайлгайд.

---

## Как это работает

1. Ты создаёшь/обновляешь Pull Request в Bitbucket
2. Бот получает уведомление, скачивает diff
3. Отправляет код ИИ на анализ
4. Через 10–30 секунд в PR появляются комментарии с замечаниями

---

## Как подключить бот к своему репозиторию

### Шаг 1. Зайди в настройки репозитория

1. Открой свой репозиторий в Bitbucket
2. Перейди в **Settings** (шестерёнка слева)
3. В разделе **WEBHOOKS** нажми **Create webhook**

### Шаг 2. Настрой Webhook

| Поле | Значение |
|---|---|
| **Name** | `JARVIS PR Review` |
| **URL** | `https://pr-review-bot.bc-dev2.int.gazprombank.ru/webhook` |
| **Status** | ✅ Active |
| **SSL verification** | ❌ Skip (если есть такая галочка) |

### Шаг 3. Выбери события (Triggers)

Отметь **только** эти три события:

- ✅ **Pull request opened** (`pr:opened`) — при создании PR
- ✅ **Source branch updated** (`pr:from_ref_updated`) — **при пуше новых коммитов в PR.**
  ⚠️ Именно это событие, а НЕ «Modified», шлёт Bitbucket на пуш. Без него повторное
  ревью на обновление PR не запустится.
- ✅ **Pull request modified** (`pr:modified`) — изменены метаданные PR (заголовок/описание/
  ревьюеры/target). Коммиты сюда НЕ входят; держим для полноты.

Остальное **НЕ** отмечай.

Нажми **Save**.

## Как пользоваться

Просто **создай PR как обычно**. Бот подключится автоматически и напишет комментарий.

**Что ты увидишь в PR:**
- 🔴 Ошибки (SQL-инъекции, отсутствие валидации)
- 🟡 Предупреждения (отсутствие eval/die, плохие практики)
- 💡 Советы по улучшению кода
- Итоговую сводку с количеством замечаний

### Как выбрать, какие комментарии показывать

По умолчанию бот публикует **ошибки и предупреждения**, а подсказки придерживает.
Если хочется иначе — напиши в **описании PR** (не в заголовке) строку:

```
@jarvis all
```

Строка должна **начинаться** с `@jarvis` — упоминание внутри текста бот не считает
командой. Место в описании любое, регистр не важен, остальной текст описания
бот не трогает.

| Команда | Что публикуется |
|---|---|
| `@jarvis errors` | только 🔴 ошибки |
| `@jarvis warnings` | 🔴 ошибки + 🟡 предупреждения (так работает по умолчанию) |
| `@jarvis all` | всё, включая 💡 подсказки |

Уровень — это **порог «и выше»**, как в логах: `warnings` не значит «только
предупреждения», ошибки при нём тоже видны.

Отдельный источник замечаний можно убрать минусом:

```
@jarvis all -codestyle
```

Источники: `perlcritic`, `codestyle`, `jarvis` (замечания самой модели). Минусы
можно комбинировать: `@jarvis all -perlcritic -codestyle`.

**Чего сделать нельзя — и это намеренно:**

- 🔴 **Ошибки не скрываются никогда** — ни порогом, ни минусом. `-codestyle`
  уберёт стилевые предупреждения и подсказки, но стилевую ошибку опубликует.
- **Скрытое видно всем.** В сводке всегда есть строка вида
  `**Фильтр:** errors (error). скрыто 12 замечаний.` — ревьюер увидит, что
  замечания были. Тихо от команды спрятать замечания меткой не получится.
- **Задним числом не работает.** Правка описания сама по себе запускает повторное
  ревью (событие `pr:modified`), и новую метку бот учтёт сразу. Но **уже
  опубликованные** комментарии останутся: удалять их бот не умеет — у него нет
  таких прав. Поэтому метку удобнее ставить сразу при создании PR.

Если бот не понял команду, он не молчит, а пишет в сводке:
`Команду «всё» не понял, работаю на уровне warnings.` Это единственный способ
заметить опечатку — Bitbucket подсказок по `@jarvis` не даёт.

> ⚠️ Опечатка в **самой метке** (`@jrvis all`) — другой случай: бот такую строку
> вообще не найдёт и молча отработает на настройках по умолчанию. Сверяйся с
> таблицей выше.

---

### Если бот молчит

- Подожди 30 секунд (большой diff может проверяться дольше)
- Если прошло 2 минуты и ничего нет — нажми **Update** в PR (просто сделай ещё один коммит, даже пустой)

### Если бот пишет «Упс! Мой мозг не ответил»

ИИ временно недоступен. Это не ошибка PR. Попробуй позже или обновить PR.

## Чего бот НЕ делает

- ❌ Не пушит код в репозиторий (только читает)
- ❌ Не мержит и не отклоняет PR
- ❌ Не блокирует merge (это advisory, а не gate)
- ❌ Не заменяет ревью сеньора

## Чего бот НЕ проверяет

- Форматирование (пробелы, отступы) — это дело линтера
- Логику бизнес-правил — только технические ошибки
- Комментарии и документацию (только код)

---

## Полезные советы

1. **Маленькие PR = лучше ревью.** Лимит объёма применяется **к каждому файлу
   отдельно** (бот ревьюит файлы по одному), так что хвост большого PR не
   теряется. Если файл всё же не влез целиком, бот честно скажет об этом в
   сводке — строкой `✂️ Показана не вся правка` с именами файлов. Молча
   недопроверенных файлов не бывает.
2. **Стайлгайд.** Бот проверяет по правилам команды. Если стайлгайд обновился — бот подхватит его автоматически.
3. **Ложные срабатывания.** ИИ может ошибаться. Если замечание неверное — просто проигнорируй его.
4. **Обновление PR.** Каждый новый пуш в PR триггерит повторную проверку.

## Как обновить бота

Бот запущен на сервере `openWebUI` через Docker. Обновление — **без флешек, через репо**:

```bash
# 1. Зайти на сервер (через WinSCP или SSH)
ssh user@openwebui-server

# 2. Скачать свежий код из репо
git pull

# 3. Пересобрать образ и перезапустить
docker build -t pr-review-bot .
docker-compose up -d
```

Базовый образ Python и pip-пакеты подтягиваются из Nexus банка — интернет не нужен.

## Частая команда (одной строкой)

```bash
git pull && docker build -t pr-review-bot . && docker-compose up -d
```

## Webhook

После перезапуска URL бота не меняется: `https://pr-review-bot.bc-dev2.int.gazprombank.ru/webhook`.
Webhook в Bitbucket перенастраивать не нужно — он привязан к URL, а не к версии бота.
